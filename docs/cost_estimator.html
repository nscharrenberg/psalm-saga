Assumptions

Prices and models

USD per million tokens on OpenRouter. These values reproduce every recorded cost_usd of the measured runs exactly. Untick a writer or judge to leave it out.

Design

Samples per item and policy setting. In the paper's design the full procedure runs 3 times, every other setup once, and paraphrase only under preserve, which gives 19 runs per item and writer.

Evaluation extras

Instruments of the judge: block that run once per experiment, not per run. None of the four measured runs included them, so their size is derived from the measured judge calls.

How the setups differ from the full procedure

modelled, not measured

Only the full procedure was measured. Each other setup uses the full procedure's tokens per stage times these factors (input / output). 0 removes a stage. Judges run on every setup.

Corpus

The 29 items of experiments/data/stories/corpus.csv. Untick an item to leave it out. Cost per item is one full-procedure run per writer, before contingency.

Measured runs

Tokens per stage in the four runs the estimate is built on. Source: final_psalm_saga_data/<writer>/<language>/<run>/calls/*.json.

Method and limits

  • Scaling. For each writer and stage, tokens = a + b × source words, a straight line through the 300-word run and the 8,521-word run. Every corpus item lies between them, so nothing is extrapolated. Writer time scales the same way.
  • Language and length are confounded. The short runs are Dutch and the long runs English, so a language effect cannot be told from a length effect. Each point is a single draw; Mistral's output is mostly reasoning and varies between runs. The contingency covers this, along with retries and failed runs.
  • Gemma's short run recorded $0 because no price was set; its tokens are priced at the rates the other Gemma run recorded.
  • Judges. Claude Sonnet 5.5, GPT-6.1 Sol and Qwen 3.8 Flash rate every run of every setup, so no measure rests on one judge. The judges read the writer's text, so their tokens are taken from the same writer's run.
  • PSALM lower anchor: one pair per item (the source against the next source of its language) × each judge. One pair costs the share of a run's judge tokens that the six PSALM calls take (85% measured).
  • Alignment lower anchor: one alignment of an item's design with another item's text, per item and writer, priced as that writer's recover stage.
  • G2 pairwise quality: every text of full (each sample), no_graph, no_feedback and paraphrase against the single call for the same item, policy and writer, in both orders, by each judge. One comparison is priced as one PSALM call (14% of a run's judge tokens).
  • Unmeasured setups. no_graph, no_feedback, paraphrase and single_call are modelled from the full procedure's stages; see the factor table. Running one item of each setup per writer would replace these guesses with measurements.
